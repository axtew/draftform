# draftform

[![CI](https://github.com/axtew/draftform/actions/workflows/ci.yml/badge.svg)](https://github.com/axtew/draftform/actions/workflows/ci.yml)
[![npm](https://img.shields.io/npm/v/draftform)](https://www.npmjs.com/package/draftform)
[![license](https://img.shields.io/npm/l/draftform)](./LICENSE)

Небольшой React-хук для плоских форм. Он знает, какие значения уже сохранены: кнопка отправки неактивна, пока ничего не изменилось, в `onSubmit` приходят только изменённые поля, а автосохранение работает без гонок.

[Демо](https://draftform.stevvy1122.workers.dev) · [English version](./README.md)

```tsx
import { useForm } from "draftform";

function SettingsForm({ settings }: { settings: Settings }) {
  const form = useForm({
    initial: settings,
    fields: { name: { required: true } },
    onSubmit: (_, { changed }) => api.patch("/settings", changed),
    autosave: true,
  });

  return (
    <form onSubmit={form.handleSubmit}>
      <input {...form.field("name")} />
      <input type="checkbox" {...form.field("notifications")} />
      <p>
        {form.pending
          ? "Сохраняем..."
          : form.dirty
            ? "Есть несохранённые изменения"
            : "Всё сохранено"}
      </p>
    </form>
  );
}
```

- **Знает, что сохранено.** У каждого поля рядом с текущим значением лежит сохранённое. `dirty`, `canSubmit` и изменённые поля в `changed` считаются из их сравнения, а после успешного запроса сохранёнными становятся ровно те значения, которые он отправил.
- **Автосохранение без гонок.** Один запрос за раз. Правки, сделанные, пока он идёт, уходят одним следующим запросом сразу после него: ничего не теряется, и старый запрос никогда не перезапишет новый.
- **Значения сохраняют тип.** Тип формы берётся из `initial`. Числовое поле хранит число, чекбокс хранит `boolean`, а между инпутом и значением стоят `parse`, `format` и `normalize`.
- **Ошибки вовремя.** Проверка идёт на каждое изменение, а ошибка показывается после ухода из поля или после отправки. `field()` ставит `aria-invalid` и `aria-describedby`, неудачная отправка переводит фокус на первое поле с ошибкой.
- **Схемы без адаптеров.** Zod, Valibot, ArkType и другие через Standard Schema, включая проверки нескольких полей сразу.
- **Маленький, без зависимостей.** 3.5 kB min + gzip, см. [Размер](#размер).

## Зачем

draftform основан на хуке форм, который я написал и использовал в своих проектах. Большинство форм там редактировали то, что уже есть: профиль, настройки, карточку. Такой форме нужно знать, что уже сохранено. Кнопка "Сохранить" неактивна, пока ничего не поменялось, в запрос уходят только изменённые поля, а после ответа отправленные значения считаются сохранёнными.

Самое сложное добавило автосохранение: пользователь продолжает печатать, пока идёт сохранение. Эти правки нельзя потерять, и старый запрос не должен прийти позже нового. Тесты покрывают эти случаи со временем, а в [демо](https://draftform.stevvy1122.workers.dev) их видно на медленном сервере с журналом запросов.

Остальное нужно любой форме: разбор и проверка каждого поля, ошибки после ухода из поля, aria-атрибуты, фокус на первой ошибке и проверка схемой, когда правил становится много.

- Без зависимостей.

## Быстрый старт

Форма редактирования профиля, который уже существует:

```tsx
import { useForm } from "draftform";

interface Profile {
  name: string;
  email: string;
  age: number;
  newsletter: boolean;
}

export function ProfileForm({ profile }: { profile: Profile }) {
  const form = useForm({
    initial: profile,
    fields: {
      name: { required: "Введите имя", normalize: (value) => value.trim() },
      email: {
        required: true,
        validate: (value) => (value.includes("@") ? null : "Введите корректный email"),
      },
      age: { required: true, validate: (value) => (value < 18 ? "С 18 лет" : null) },
    },
    // Только то, что отличается от сохранённого: тело PATCH-запроса.
    onSubmit: (_, { changed }) => api.patch("/me", changed),
  });

  const error = (name: keyof Profile) => {
    const message = form.fields[name].visibleError;
    return message === null ? null : <p id={form.errorId(name)}>{message}</p>;
  };

  return (
    <form onSubmit={form.handleSubmit}>
      <label htmlFor={form.fieldId("name")}>Имя</label>
      <input {...form.field("name")} />
      {error("name")}

      <label htmlFor={form.fieldId("email")}>Email</label>
      <input type="email" {...form.field("email")} />
      {error("email")}

      <label htmlFor={form.fieldId("age")}>Возраст</label>
      <input type="number" {...form.field("age")} />
      {error("age")}

      <label>
        <input type="checkbox" {...form.field("newsletter")} /> Присылать рассылку
      </label>

      {form.submitError !== null && (
        <p role="alert">Не получилось сохранить, попробуйте ещё раз.</p>
      )}
      <button type="submit" disabled={!form.canSubmit}>
        {form.pending ? "Сохраняем..." : "Сохранить"}
      </button>
    </form>
  );
}
```

- Тип формы - `Profile`, он взят из `initial`. `form.field("nmae")` не скомпилируется.
- `field(name)` даёт инпуту `name`, `id`, `value` (или `checked`), `onChange`, `onBlur`, `ref` и aria-атрибуты.
- `canSubmit` равен `true`, когда форма валидна, в ней есть изменения и сохранение сейчас не идёт.
- `onSubmit` может вернуть промис. Когда он выполнится, полученные значения станут сохранёнными, и кнопка снова станет неактивной.

## Поля

Настройки полей лежат в `fields`, по имени поля. Все они необязательные.

```tsx
const form = useForm({
  initial: { title: "", priceCents: 0, discount: null as number | null },
  fields: {
    title: { required: true, normalize: (value) => value.trim() },
    // В форме копейки, в инпуте рубли.
    priceCents: {
      parse: (input) => Math.round(Number(input) * 100),
      format: (value) => (value / 100).toFixed(2),
      validate: (value) => (value > 0 ? null : "Должно быть больше нуля"),
    },
  },
});
```

- `parse` превращает текст инпута в значение, `format` превращает значение в текст инпута.
- `normalize` применяется к каждому новому значению, прежде чем его сохранить и проверить: trim, нижний регистр. Пока пользователь печатает, инпут показывает текст как есть, поэтому пробел между двумя словами не пропадает. После ухода из поля показывается уже сохранённое значение.
- `required` не пропускает строку из одних пробелов, `null`, `NaN` и `false`. `true` даёт сообщение "Required", строка сама становится сообщением.
- `validate(value, values)` получает сохранённое в форме значение (после `parse` и `normalize`) и все текущие значения, так что может сравнивать поля. Возвращает сообщение или `null` / `undefined`, если всё в порядке. Сначала проверяется `required`, поэтому `validate` никогда не повторяет "Required".
- Все проверки идут на каждое изменение, для всех полей. Правило вроде "повторите пароль" никогда не показывает устаревший результат.

### Числа и пустой инпут

Без `parse` поле сохраняет тот тип, с которым начало. Числовое поле или любой `<input type="number">` даёт число. Пустой инпут даёт `NaN`, или `null`, если поле начинало с `null`, как `discount` выше. Оба показываются пустым инпутом, и оба считаются пустыми для `required`.

Если числовое поле должно становиться `null` каждый раз, когда его очищают, это пишется в `parse`:

```tsx
const form = useForm({
  initial: { age: 30 as number | null },
  fields: {
    age: { parse: (input) => (input.trim() === "" ? null : Number(input)) },
  },
});
```

### Чекбоксы

Поле типа `boolean` - это чекбокс: `field()` возвращает `checked` вместо `value`. С `required` галочка должна стоять, как с HTML-атрибутом.

```tsx
const form = useForm({
  initial: { terms: false },
  fields: { terms: { required: "Примите условия, чтобы продолжить" } },
});

<input type="checkbox" {...form.field("terms")} />;
```

У чекбокса два состояния, поэтому `boolean | null` и необязательный `boolean` - ошибка типов. Для третьего состояния ("ещё не ответил") подойдёт группа radio над типом вроде `"yes" | "no" | null`.

### Radio

`field(name, { radio: option })` возвращает пропсы одной radio-кнопки. `type="radio"` пишется руками. Вариант должен подходить под тип поля, и у каждого варианта свой `id`, `fieldId(name, option)`, для подписи:

```tsx
type Plan = "free" | "pro" | "team";

const form = useForm({ initial: { plan: "free" as Plan } });

<fieldset>
  <legend>Тариф</legend>
  {(["free", "pro", "team"] as const).map((plan) => (
    <div key={plan}>
      <input type="radio" {...form.field("plan", { radio: plan })} />
      <label htmlFor={form.fieldId("plan", plan)}>{plan}</label>
    </div>
  ))}
</fieldset>;
```

`<select>` и `<textarea>` принимают `field(name)` так же, как инпут.

## Ошибки и touched

У каждого поля в `form.fields` две ошибки:

- `error` - текущая ошибка. Она считается с первого рендера, трогали поле или нет. Если подставленные данные уже неверны, форма сразу невалидна.
- `visibleError` - ошибка, которую нужно показать. Она появляется, когда поле тронули (ушли из него), или после отправки, которая трогает все поля. Ошибка из `setError` видна сразу.

Пользователь, который проходит Tab'ом по пустой форме, не видит красных полей, пока из них не ушёл, но `valid` и `canSubmit` верны с самого начала.

```tsx
const { visibleError, touched, dirty } = form.fields.email;
```

## Доступность

- Пока ошибка поля видна, у инпута стоит `aria-invalid="true"`, а `aria-describedby` указывает на `errorId(name)`. Этот id нужно поставить на элемент с сообщением, как в [быстром старте](#быстрый-старт).
- `fieldId(name)` - это `id` инпута, для `<label htmlFor>`. Id строятся через `useId`, поэтому две формы на одной странице не пересекаются.
- Отправка невалидной формы переводит фокус на первое поле с ошибкой, в порядке `initial`. Поле без элемента (свой компонент, который работает через `setValue`) или выключенное поле пропускается. В группе radio фокус получает отмеченный вариант, как при нажатии Tab.

## Сохранённые значения и dirty

Сохранённое значение поля - это то, что лежит на сервере. По умолчанию это начальное значение, поэтому форма редактирования стартует чистой.

- Поле `dirty`, когда его значение отличается от сохранённого. Если изменить значение, а потом вернуть как было, поле снова чистое.
- Форма `dirty`, когда `dirty` хотя бы одно поле.
- `onSubmit` получает `{ changed }`: только изменённые поля.
- Когда `onSubmit` выполнится, сохранёнными станут ровно те значения, которые он получил. Поле, изменённое, пока шёл запрос, сохраняет новое значение и остаётся `dirty`, поэтому его отправит следующее сохранение.

У формы создания часто есть значения по умолчанию, которые тоже нужно отправить: название, видимость. Без правок такая форма чистая, и `submit()` её не отправит. Опция `saved` говорит форме, что сохранено на самом деле:

```tsx
const form = useForm({
  initial: { title: "Новая доска", visibility: "team" },
  // Ничего ещё не создано: значения по умолчанию считаются изменениями, форму можно отправить сразу.
  saved: { title: "", visibility: "" },
  onSubmit: (values) => api.post("/boards", values),
});
```

## Отправка

`handleSubmit` ставится на `<form onSubmit>` и не даёт странице перезагрузиться. `submit()` делает то же без события и возвращает `Promise<boolean>`:

```tsx
async function saveAndClose() {
  if (await form.submit()) navigate("/settings");
}
```

Что делает `submit()`:

1. Помечает все поля тронутыми, чтобы показались их ошибки.
2. Если форма невалидна, переводит фокус на первое поле с ошибкой и возвращает `false`.
3. Если ничего не изменилось, возвращает `false`.
4. Иначе вызывает `onSubmit(values, { changed })` и возвращает `true`, когда он успешно выполнится.

Пока идёт запрос, `pending` равен `true`, а `canSubmit` равен `false`. Если `onSubmit` бросит ошибку или вернёт отклонённый промис, `submit()` вернёт `false`, ошибка попадёт в `onError` и останется в `submitError` до следующего успеха или сброса. Форма остаётся `dirty`, так что пользователь может попробовать ещё раз. Сама по себе отправка не повторяется.

Отправка во время идущего сохранения ждёт его, а потом отправляет только то, что ещё не сохранено. Двойной клик даёт один запрос.

`disabled={!form.canSubmit}` держит кнопку неактивной, пока нечего сохранять. Если кнопка должна быть активна всегда, чтобы клик показывал ошибки и переводил фокус, подойдёт `disabled={form.pending}`.

`onSubmit` и `onError` берутся из последнего рендера, поэтому в них можно использовать пропсы и состояние без устаревших значений.

## Сброс

```tsx
// Кнопка "Отмена": назад к начальным значениям.
<button type="button" onClick={() => form.reset()}>
  Отмена
</button>;

// Данные пришли после монтирования: они становятся и текущими, и сохранёнными.
form.reset(user);
```

- `reset()` возвращает значения к `initial`, а сохранённые значения к `initial` с учётом опции `saved`.
- `reset(values)` делает переданные значения текущими и сохранёнными. Поля, которых нет в `values`, возвращаются к `initial`, а ключи, которых нет среди полей, пропускаются, так что можно передать целый объект с сервера.
- Оба варианта очищают `touched`, ошибки из `setError` и `submitError`.
- Идущее сохранение продолжается, и `pending` остаётся `true`, пока оно не закончится, но его результат уже ничего не помечает сохранённым.
- Правки, которые автосохранение ещё не отправило, отбрасываются: кнопка "Отмена" не должна их сохранять. Чтобы их не потерять, перед `reset` нужно вызвать `await form.flush()`.

### resetKey

Форме, которая переключается между записями, передают id записи в `resetKey`:

```tsx
function UserForm({ user }: { user: User }) {
  const form = useForm({
    initial: user,
    resetKey: user.id,
    onSubmit: (_, { changed }) => api.patch(`/users/${user.id}`, changed),
    autosave: true,
  });
  // ...
}
```

Когда `resetKey` меняется, форма сбрасывается к `initial` и `saved` этого рендера ещё до рендера дочерних компонентов, так что они никогда не покажут значения старой записи рядом с новой. Правки, которые автосохранение ещё не отправило, уходят сразу, с `onSubmit` старой записи: они попадают в ту запись, где их сделали.

`initial` читается только при монтировании и при сбросе. Новый объект в `initial` с тем же `resetKey` не трогает то, что печатает пользователь.

## Автосохранение

```tsx
const form = useForm({
  initial: settings,
  onSubmit: (_, { changed }) => api.patch("/settings", changed),
  autosave: true, // через 500 мс после последнего изменения, или { delay: 1000 }
});
```

- Форма сохраняется, когда пользователь перестал её править на время задержки. Каждое изменение запускает ожидание заново.
- Сохраняется только валидная форма с изменениями. Невалидная ждёт следующего изменения, не трогая поля и не переводя фокус.
- Одно сохранение за раз. Изменения, сделанные во время сохранения, уходят одним следующим сохранением сразу после него, с последними значениями.
- Идущий запрос никогда не отменяется. Отмена останавливает ожидание в браузере, но не работу на сервере, и старый запрос мог бы закончиться после нового и перезаписать его. Ожидание сохраняет порядок.
- Неудачное сохранение само не повторяется: о нём сообщают `submitError` и `onError`, а снова попробует следующее изменение или `flush()`.
- `flush()` сохраняет сразу, без ожидания: перед уходом со страницы или по кнопке "Сохранить сейчас". Он ждёт идущее сохранение, потом отправляет то, что ещё не сохранено, и возвращает `true`, когда сохранено всё.
- Изменение, которое ещё ждёт отправки, когда форма размонтируется, сохраняется сразу.

```tsx
<p aria-live="polite">
  {form.pending ? "Сохраняем..." : form.dirty ? "Есть несохранённые изменения" : "Всё сохранено"}
</p>
```

## Проверка схемой

Подходит любая [Standard Schema](https://standardschema.dev): Zod, Valibot, ArkType и другие. draftform от них не зависит, он знает только интерфейс.

```tsx
import { useForm } from "draftform";
import * as z from "zod";

const signUpSchema = z
  .object({
    email: z.email("Введите корректный email"),
    password: z.string().min(8, "Не меньше 8 символов"),
    repeat: z.string(),
  })
  .refine((values) => values.password === values.repeat, {
    message: "Пароли не совпадают",
    path: ["repeat"],
  });

const form = useForm({
  initial: { email: "", password: "", repeat: "" },
  fields: { email: { required: "Введите email" } },
  schema: signUpSchema,
  onSubmit: (values) => api.post("/sign-up", values),
});
```

То же на Valibot:

```tsx
import * as v from "valibot";

const signUpSchema = v.pipe(
  v.object({
    email: v.pipe(v.string(), v.email("Введите корректный email")),
    password: v.pipe(v.string(), v.minLength(8, "Не меньше 8 символов")),
    repeat: v.string(),
  }),
  v.forward(
    v.partialCheck(
      [["password"], ["repeat"]],
      (input) => input.password === input.repeat,
      "Пароли не совпадают",
    ),
    ["repeat"],
  ),
);
```

- Схема проверяет всю форму при каждом изменении значения.
- Ошибка схемы принадлежит полю, имя которого стоит первым в её `path`. `refine` выше ставит своё сообщение на `repeat`.
- Ошибка без `path` или с `path`, который не указывает на поле, попадает в `form.formError`. Она показывается после отправки, как ошибки полей, но делает форму невалидной и до этого.
- Порядок для поля: ошибка из `setError`, потом `required`, потом `validate`, потом схема. Сообщение схемы поле показывает, только когда его собственные проверки прошли.
- Схема только проверяет. `onSubmit` получает значения формы, а не результат схемы, поэтому её преобразования и значения по умолчанию не применяются.
- Схема другой формы - ошибка типов: поле другого типа или ни одного общего поля с формой.
- Только синхронные схемы. Схема, которая отвечает промисом, бросает ошибку.

Проверка, которой нужен сервер (занят ли email), делается в `onSubmit`, а её результат передаётся полю через `setError`:

```tsx
const form = useForm({
  initial: { email: "", password: "" },
  onSubmit: async (values) => {
    try {
      await api.post("/sign-up", values);
    } catch (error) {
      if (error instanceof EmailTakenError) {
        form.setError("email", "Этот email уже зарегистрирован");
      }
      // Бросаем дальше: форма останется несохранённой, и её можно будет отправить снова.
      throw error;
    }
  },
});
```

## Свои компоненты

Компонент, который не является инпутом (выбор даты, выбор цвета, переключатель), работает через `values` и `setValue`:

```tsx
<ColorPicker value={form.values.color} onChange={(color) => form.setValue("color", color)} />
```

- `setValue(name, value)` принимает значение или функцию от текущего: `form.setValue("count", (count) => count + 1)`. Несколько вызовов в одном обработчике применяются все, по порядку. `normalize` поля срабатывает, автосохранение видит изменение.
- `setError(name, message)` ставит ошибку снаружи, обычно с сервера. Она видна сразу и держится, пока поле не изменят. `null` её убирает.

`field()` возвращает `ref`-колбэк: через него форма ставит фокус на поле после неудачной отправки. На DOM-элементах это работает в любой версии React. Если разворачивать `field()` на свой компонент, React 19 передаст `ref` как обычный проп, а в React 18 компонент нужно обернуть в `forwardRef`, иначе фокус при ошибке это поле пропустит. Чтобы сохранить и свой ref, вызовите оба: `ref={(element) => { props.ref(element); myRef.current = element; }}`.

## С TanStack Query

TanStack Query загружает запись и отправляет запрос, draftform держит правки. `mutateAsync` возвращает промис, поэтому форма ждёт его, при успехе помечает отправленные значения сохранёнными, а при неудаче получает ошибку:

```tsx
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import { useForm } from "draftform";

const EMPTY: Profile = { id: 0, name: "", email: "", newsletter: false };

export function ProfilePage() {
  const queryClient = useQueryClient();
  const { data } = useQuery({ queryKey: ["profile"], queryFn: fetchProfile });
  const mutation = useMutation({
    mutationFn: (changed: Partial<Profile>) => patchProfile(changed),
    onSuccess: (profile) => queryClient.setQueryData(["profile"], profile),
  });

  const form = useForm({
    initial: data ?? EMPTY,
    // Сброс к `initial`, когда пришли данные, и ещё раз для другой записи.
    resetKey: data?.id,
    onSubmit: (_, { changed }) => mutation.mutateAsync(changed),
    autosave: true,
  });

  if (data === undefined) return <p>Загрузка...</p>;

  return (
    <form onSubmit={form.handleSubmit}>
      <input {...form.field("name")} />
      <input type="email" {...form.field("email")} />
      <input type="checkbox" {...form.field("newsletter")} />
    </form>
  );
}
```

Когда приходят данные, `resetKey` меняется с `undefined` на id, и форма берёт данные как начальные и сохранённые значения. Повторный запрос или `setQueryData` после сохранения даёт новый объект `data` с тем же id, и форма не трогает то, что печатает пользователь. `id` здесь - поле без инпута: оно не меняется, поэтому никогда не попадает в `changed`.

`reset(data)` в эффекте на `data` тоже работает. Только он срабатывает на каждый новый `data`, включая повторную загрузку, и каждый раз отбрасывает неотправленные правки. Проще всего рендерить форму, только когда данные уже загружены.

## Когда лучше взять react-hook-form

draftform рассчитан на плоские формы, до нескольких десятков полей. [react-hook-form](https://react-hook-form.com) (или TanStack Form) лучше взять, когда нужны:

- **Массивы полей**: список адресов, строки, которые пользователь добавляет и удаляет.
- **Вложенные объекты**: значения вроде `address.city`. В draftform значения - это строки, числа, `boolean` и `null`.
- **Сотни полей или тяжёлые инпуты.** draftform контролируемый: каждое нажатие клавиши рендерит форму. react-hook-form держит инпуты неконтролируемыми и рендерит гораздо реже.
- **Асинхронная проверка поля** с задержкой, например "свободно ли имя" прямо во время ввода. В draftform проверка через сервер делается в `onSubmit` с `setError`.
- **Большая экосистема**: резолверы, devtools, обвязки для UI-китов, много ответов в интернете.

draftform подходит для форм редактирования записи и страниц настроек: профиль, аккаунт, карточка, с автосохранением или без. Небольшие формы входа и регистрации тоже работают хорошо. В react-hook-form "сохранённые" значения - это `reset(values)` после каждого сохранения, а автосохранение - это `watch`, задержка и своя защита от параллельных запросов.

## API

### Опции useForm

| Опция      | Тип                                                        | По умолчанию | Что делает                                                                                                                    |
| ---------- | ---------------------------------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `initial`  | объект со значениями `string`, `number`, `boolean`, `null` | обязательна  | Начальные значения, из них выводится тип формы. Читаются при монтировании и при каждом сбросе.                                |
| `fields`   | `{ [name]: FieldOptions }`                                 | нет          | `required`, `parse`, `format`, `normalize`, `validate` для каждого поля. См. [Поля](#поля).                                   |
| `schema`   | Standard Schema                                            | нет          | Проверяет всю форму при каждом изменении. Только синхронная. См. [Проверка схемой](#проверка-схемой).                         |
| `saved`    | `Partial<V>`                                               | `initial`    | Значения, которые считаются сохранёнными: для форм создания, где значения по умолчанию нужно отправить.                       |
| `onSubmit` | `(values: V, { changed }) => unknown`                      | нет          | Сохраняет. Может вернуть промис; ошибка или отклонённый промис означают неудачу. Вызывают `submit`, `flush` и автосохранение. |
| `onError`  | `(error: unknown) => void`                                 | нет          | Получает то, что бросил `onSubmit`.                                                                                           |
| `autosave` | `boolean` или `{ delay?: number }`                         | выключено    | Сохраняет валидную форму с изменениями через `delay` мс без правок (по умолчанию 500). См. [Автосохранение](#автосохранение). |
| `resetKey` | `unknown`                                                  | нет          | Когда меняется (`Object.is`), форма сбрасывается. Сюда передают id редактируемой записи.                                      |

### FieldOptions

| Опция       | Тип                                                    | Что делает                                                                   |
| ----------- | ------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `required`  | `boolean` или `string`                                 | Поле не должно быть пустым. Строка - это сообщение, `true` даёт "Required".  |
| `parse`     | `(input: string) => T`                                 | Текст инпута в значение. Для чекбоксов не вызывается.                        |
| `format`    | `(value: T) => string`                                 | Значение в текст инпута. По умолчанию `null` и `NaN` показываются пустыми.   |
| `normalize` | `(value: T) => T`                                      | Применяется к каждому новому значению, прежде чем его сохранить и проверить. |
| `validate`  | `(value: T, values: V) => string \| null \| undefined` | Возвращает сообщение или `null` / `undefined`, если значение в порядке.      |

### Форма

| Свойство                 | Тип                                           | Что это                                                                                        |
| ------------------------ | --------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `values`                 | `V`                                           | Текущие значения. Объект меняется, только когда меняется значение.                             |
| `fields`                 | `{ [name]: FieldState }`                      | Состояние каждого поля, ниже.                                                                  |
| `dirty`                  | `boolean`                                     | Хотя бы одно поле отличается от сохранённого значения.                                         |
| `valid`                  | `boolean`                                     | Ни у одного поля нет ошибки, и нет `formError`.                                                |
| `formError`              | `string \| null`                              | Ошибка схемы, которая не относится ни к одному полю. Видна после отправки.                     |
| `canSubmit`              | `boolean`                                     | Валидна, есть изменения, сохранение не идёт.                                                   |
| `pending`                | `boolean`                                     | Идёт сохранение: из `submit`, `flush` или автосохранения.                                      |
| `submitError`            | `unknown`                                     | Что бросил последний неудачный `onSubmit`; `null` после успеха или сброса.                     |
| `field(name)`            | пропсы                                        | Пропсы для инпута, `<select>` или `<textarea>`; для поля `boolean` - `checked` вместо `value`. |
| `field(name, { radio })` | пропсы                                        | Пропсы одной radio-кнопки группы.                                                              |
| `setValue`               | `(name, value \| (current) => value) => void` | Ставит значение из кода.                                                                       |
| `setError`               | `(name, message \| null) => void`             | Ставит ошибку снаружи. Видна сразу, снимается следующей правкой поля.                          |
| `fieldId`                | `(name, option?) => string`                   | `id` инпута или одной radio-кнопки.                                                            |
| `errorId`                | `(name) => string`                            | `id` для элемента с ошибкой поля.                                                              |
| `submit`                 | `() => Promise<boolean>`                      | Трогает все поля, проверяет, сохраняет. `true`, когда значения сохранены.                      |
| `handleSubmit`           | `(event?) => void`                            | `submit()` для `<form onSubmit>`, не даёт странице перезагрузиться.                            |
| `flush`                  | `() => Promise<boolean>`                      | Сохраняет сразу, без ожидания автосохранения и не трогая поля. `true`, когда сохранено всё.    |
| `reset`                  | `(values?: Partial<V>) => void`               | Начинает заново: к `initial` или к переданным значениям как текущим и сохранённым.             |

### FieldState

| Свойство       | Тип              | Что это                                                          |
| -------------- | ---------------- | ---------------------------------------------------------------- |
| `value`        | `T`              | Значение в форме, после `parse` и `normalize`.                   |
| `saved`        | `T`              | Значение, которое считается сохранённым.                         |
| `error`        | `string \| null` | Текущая ошибка, трогали поле или нет.                            |
| `visibleError` | `string \| null` | Ошибка для показа: после ухода из поля, отправки или `setError`. |
| `dirty`        | `boolean`        | Значение отличается от сохранённого.                             |
| `touched`      | `boolean`        | Из поля хотя бы раз ушли, или форму отправили.                   |

Пропсы из `field()`: `name`, `id`, `value` или `checked`, `onChange`, `onBlur`, `ref`, `aria-invalid` и `aria-describedby`.

Пакет также экспортирует типы `Form`, `FormOptions`, `FieldOptions`, `FieldsOptions`, `FieldState`, `FieldValue`, `FormValues`, `FieldName`, `FieldProps`, `InputFieldProps`, `CheckboxFieldProps`, `RadioFieldProps`, `RadioOptions`, `BaseFieldProps`, `FieldElement`, `FieldRef`, `SubmitContext`, `AutosaveOptions`, `FormSchema`, `CheckValues`, `StandardSchemaV1` и `StandardTypedV1`.

## Размер

Одна и та же небольшая форма в каждой библиотеке: профиль с именем, email, городом и чекбоксом рассылки, обязательные поля с проверками, ошибки после ухода из поля, кнопка отправки, неактивная без изменений, и отправленные значения, которые после сохранения считаются сохранёнными. Минификация esbuild, React не считается, зависимости библиотек и сам компонент формы считаются. Метод и код: [`bench/size`](./bench/size), запуск: `pnpm bench:size`.

| Библиотека           | min + gzip | Оговорки                                                                                                                         |
| -------------------- | ---------: | -------------------------------------------------------------------------------------------------------------------------------- |
| **draftform**        | **4.0 kB** | сохранённые значения, `changed` и автосохранение из коробки; нет массивов полей, вложенных объектов и асинхронных проверок полей |
| react-hook-form      |    13.1 kB | неконтролируемые инпуты, массивы полей, резолверы, асинхронные проверки; автосохранение руками через `watch`                     |
| formik               |    13.7 kB | массивы полей, Yup через `validationSchema`; автосохранение руками                                                               |
| @tanstack/react-form |    18.0 kB | массивы полей, вложенные значения, асинхронные проверки с задержкой, Standard Schema; автосохранение руками через listener       |

В каждой строке есть и компонент формы, около 0.5 kB; сам draftform весит 3.5 kB. Замер в ноябре 2026, версии в [`bench/size/package.json`](./bench/size/package.json).
